# Hash-table collision handling

[S1] A hash maps each key to a bucket index; finite buckets make collisions inevitable. [S2] Colliding keys share a bucket, e.g. via chaining each bucket holds a small list. [S3] Lookup hashes, scans only that bucket, and compares full keys, so the right value returns. [S4] Good hashing spreads keys; worst case degrades toward scanning a long chain.
